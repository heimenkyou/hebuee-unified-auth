# 业务系统接入

完成统一身份认证后，客户端需进一步建立并验证目标业务系统的用户会话。本文记录服务大厅课表应用的认证链路与会话验证方法，并提供其他校内业务系统的接入线索。

## 服务大厅课表

登录示例以课表应用入口发起认证，典型链路如下：

```text
GET  https://ehall.hebuee.edu.cn/qljfwappnew/sys/lwPsMyCurriculum/*default/index.do
302  https://authserver.hebuee.edu.cn/authserver/login?service=<服务大厅地址>
POST https://authserver.hebuee.edu.cn/authserver/login
302  https://ehall.hebuee.edu.cn/qljfwappnew/sys/lwPsMyCurriculum/*default/index.do?ticket=ST-...
200  服务大厅页面
```

在整个认证及后续访问流程中，客户端必须复用同一个 Cookie 容器，以确保认证服务器与服务大厅建立的会话状态能够持续生效。

### 服务大厅会话验证

在完成登录重定向后，可向服务大厅用户信息接口发起请求以验证会话有效性：

```text
GET https://ehall.hebuee.edu.cn/jsonp/userInfo.json
```

当响应 JSON 中的 `hasLogin` 字段为 `true` 时，表明服务大厅会话已成功建立；若为 `false` 则表示尚未登录。若会话有效，接口通常还会返回非空的 `userName`（用户姓名），可用于验证当前登录用户的身份。

### 课表应用初始化

在调用课表业务接口前，客户端还需要完成服务大厅的应用角色初始化流程：

1. 请求 `roles.do`，获取当前账号的角色列表。
2. 请求 `setupRole.do`，设置选定的业务角色。
3. 依前端页面加载顺序请求 `menu.do`，获取应用菜单。

上述步骤为服务大厅课表应用特有的初始化流程；对接其他校内业务系统时，需根据具体系统的接口规范建立会话并完成相应的状态初始化。

## WebVPN 与教务系统

根据调研记录，WebVPN 链路需通过特定的代理路径访问统一认证页面，再经由 Ticket 和 Token 的重定向建立 WebVPN 代理会话，最终访问教务系统的 `/sso/jziotlogin` 单点登录入口。由于 WebVPN 采用了域名与路径代理重写机制，接入前需单独对其表单 Action 地址、跳转流程及会话维持方式进行抓包分析与验证。

## OA 申报与碳普惠平台

若需对接 OA 申报平台或碳普惠平台，需单独梳理并确认各自的认证入口、回调跳转地址、业务系统会话机制以及各类平台 Token 的获取方式。
