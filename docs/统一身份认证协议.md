# 统一身份认证协议

本文记录以服务大厅为入口发起统一身份认证时的 HTTP 请求流程、表单字段规范及密码加密实现方式。认证服务器地址为 `https://authserver.hebuee.edu.cn`；业务系统的入口及认证后的会话建立方式详见[业务系统接入](业务系统接入.md)。

## 请求流程

1. 客户端访问业务系统入口，未认证时服务器将 302 重定向至 `/authserver/login?service=...`。
2. 客户端解析登录页面的 `casLoginForm` 表单，提取表单提交地址（action）、隐藏字段及 `pwdDefaultEncryptSalt`。
3. 客户端检查是否需要验证码：`GET /authserver/needCaptcha.html?username=<账号>&pwdEncrypt2=pwdEncryptSalt`。返回 `true` 或 `true::::<新盐值>` 时，读取 `GET /authserver/captcha.html?ts=<时间戳>` 的图片并识别，将结果填入 `captchaResponse`。
4. 客户端使用页面下发的盐值加密密码，将密文、账号、验证码（启用时）及隐藏字段 POST 提交至表单 action 地址。验证码错误时页面会提示「无效的验证码」，客户端换图重试。
5. 认证服务器携带 `ticket` 参数 302 重定向回业务系统。客户端需使用同一个 Cookie 容器跟随重定向，进而完成后续业务系统的会话建立。

各业务系统独立负责建立自身的用户会话。客户端需根据业务系统的响应内容判断会话建立是否成功；服务大厅的验证方式详见[服务大厅会话验证](业务系统接入.md#服务大厅会话验证)。

## 登录表单

| 字段 | 用途 |
|---|---|
| `username` | 学号或工号 |
| `password` | 加密后的密码密文 |
| `lt`、`execution` | 页面生成的认证上下文 |
| `_eventId` | 事件标识，通常为 `submit` |
| `dllt` | 登录类型，通常为 `userNamePasswordLogin` |
| `rmShown` | 记住登录标记 |
| `captchaResponse` | 启用验证码时动态出现的字段 |
| `pwdDefaultEncryptSalt` | 密码加密所使用的页面动态盐值 |

每次发起认证时，客户端都应动态解析登录页面中的隐藏字段与盐值。`lt`、`execution` 等字段为服务端动态生成的认证上下文，不能硬编码在程序中。

## 密码加密

登录页面采用 AES-CBC 模式加密密码。本项目的具体实现步骤如下：

1. 从大小写英文字母与数字中随机生成 64 位字符作为前缀，再生成 16 位字符作为初始向量（IV）。
2. 将前缀与明文密码拼接，并转换为 UTF-8 编码字节流。
3. 去除服务端下发的盐值首尾空白字符，将盐值的 UTF-8 字节作为 AES 密钥。
4. 对第 2 步得到的字节流进行 PKCS7 填充，随后使用 AES-CBC 算法加密。
5. 将加密后的密文进行 Base64 编码，作为表单的 `password` 字段提交。

本项目使用的随机字符集为 `A-Z`、`a-z` 与 `0-9`。学校原版登录页面 JS 脚本所采用的字符集为 `ABCDEFGHJKMNPQRSTWXYZabcdefhijkmnprstwxyz2345678`（去除了部分易混淆字符）。两种字符集均可正常生成前缀与 IV 并通过认证测试；若使用其他语言实现，建议结合学校当前前端脚本与实际测试结果验证兼容性。生成的 IV 仅用于加密计算，不需要作为单独的表单字段提交。

## 验证码与认证结果

同一账号连续 3 次输错密码后，服务端按账号维度启用图形验证码；触发后换会话、换 IP 仍会要求验证码，通常需等待计数过期或成功登录后解除。

验证码检测接口返回 `false` 时无需验证码；返回 `true` 或 `true::::<新盐值>` 时，客户端需读取 `captcha.html` 图片、识别四位字母数字，并在登录表单中提交 `captchaResponse`（校验不区分大小写；服务端同时下发新盐值时，密码必须使用新盐值重新加密）。验证码错误时页面提示「无效的验证码」；验证码通过但密码错误时提示「您提供的用户名或者密码有误」。`scripts/login.py` 演示了使用 `ddddocr` 识别、最多尝试 3 次（含换图重试）的写法；最小 `Client.login` 在需要验证码时直接抛出 `CaptchaRequired`，可按需复制示例中的处理。

若提交表单后的响应页面中仍包含 `casLoginForm`，表明认证未成功；若重定向后的最终地址仍停留在认证服务器域名，同样不能视作业务系统登录成功。针对密码过期、强制完善个人信息等特殊提示页面，由调用方按业务规则继续处理。

## 重复登录与踢出会话

同一账号在其他位置仍有登录会话时，新的登录会进入「踢出会话」确认页。向页面中的 `continue` 表单提交 `execution` 与 `_eventId=continue` 后，服务端会注销旧会话并继续本次登录。`scripts/login.py` 中的 `login_with_captcha` 演示了这段处理，可按需复制；注销失败时抛出 `AuthenticationError`。

## 会话与安全

客户端必须为每个用户维护独立的 Cookie 容器，且全流程均应通过 HTTPS 与认证服务器及业务系统通信。Cookie、Ticket 票据、加密密文以及携带敏感参数的 URL 均属于敏感凭据，应防止泄露。此外，统一认证服务端会话的具体有效时长尚待实测确认。
