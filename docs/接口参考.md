# 统一身份认证接口参考

本文按请求顺序列出统一认证涉及的 HTTP 接口、参数和响应，供接入或排查时直接查阅。表单字段的加密规则见 [统一身份认证协议](统一身份认证协议.md)。示例中的账号、Ticket 与 Cookie 值均已省略。

## 1. 通用约定

- **认证服务器**：`https://authserver.hebuee.edu.cn`
- **业务系统入口**：由各业务系统提供，统一认证通过 `service` 参数回跳。
- **会话**：整个流程复用同一个 Cookie 容器；认证服务器与业务系统的 Cookie 分开保存，但由同一个客户端实例携带。
- **重定向**：认证流程依赖 302 跳转，客户端需要跟随 `Location`，不能只看首次响应。
- **请求头**：默认使用浏览器风格 `User-Agent`；表单提交使用 `application/x-www-form-urlencoded`。
- **响应类型**：登录页、错误页和踢出会话页为 `text/html; charset=utf-8`；验证码图片为 `image/jpeg`；`needCaptcha.html` 的响应头是 HTML，响应体是纯文本。

## 2. 接口总表

| 顺序 | 方法与路径 | 用途 |
| --- | --- | --- |
| 1 | `GET <业务系统入口>` | 触发认证跳转 |
| 2 | `GET /authserver/login?service=<业务入口>` | 获取登录页与动态字段 |
| 3 | `GET /authserver/needCaptcha.html?username=<账号>&pwdEncrypt2=pwdEncryptSalt` | 查询是否需要验证码 |
| 4 | `GET /authserver/captcha.html?ts=<毫秒时间戳>` | 获取验证码图片（仅需要时） |
| 5 | `POST /authserver/login?service=<业务入口>` | 提交账号、密码与验证码 |
| 6 | `POST <当前认证地址>` | 提交踢出会话确认（仅在出现确认页时） |
| 7 | `GET <service 回调地址>?ticket=<ST-...>` | 携带 Ticket 回到业务系统 |

## 3. 接口明细

### 3.1 触发认证

```http
GET <业务系统入口>
```

未登录时返回 302，跳转到：

```text
https://authserver.hebuee.edu.cn/authserver/login?service=<URL 编码后的业务系统入口>
```

已有有效会话时，直接 302 回业务系统或返回业务系统页面。判断是否需要登录，以最终页面是否出现登录表单为准。

### 3.2 获取登录页

```http
GET /authserver/login?service=<URL 编码后的业务系统入口>
```

响应为 200 HTML。页面中的 `casLoginForm` 表单包含以下内容：

| 元素 | 用途 |
| --- | --- |
| `form#casLoginForm` 的 `action` | 登录提交地址，通常为 `/authserver/login?service=...` |
| `#username` / `#password` | 账号与密码输入框 |
| `#pwdDefaultEncryptSalt` | 密码加密盐值，每次页面加载动态生成 |
| `lt`、`execution`、`_eventId`、`dllt`、`rmShown` | 隐藏字段，提交时原样带回 |

`lt`、`execution` 与盐值必须在每次登录时重新解析，不能跨会话复用。

### 3.3 查询验证码状态

```http
GET /authserver/needCaptcha.html?username=<账号>&pwdEncrypt2=pwdEncryptSalt
```

| 参数 | 说明 |
| --- | --- |
| `username` | 学号或工号 |
| `pwdEncrypt2` | 固定值 `pwdEncryptSalt`，不是实际盐值 |

响应状态 200，响应头为 `text/html;charset=utf-8`，响应体为纯文本：

| 响应体 | 含义 |
| --- | --- |
| `false` | 当前账号不需要验证码，可直接提交登录表单 |
| `true` | 需要验证码 |
| `true::::<新盐值>` | 需要验证码，且服务端下发了新的密码加密盐值；提交时使用新盐值加密密码 |

验证码状态按账号维度生效，换会话或换网络环境仍会保持。

### 3.4 获取验证码图片

```http
GET /authserver/captcha.html?ts=<毫秒时间戳>
```

| 参数 | 说明 |
| --- | --- |
| `ts` | 时间戳，仅用于避免缓存 |

响应为 `image/jpeg`，图片与当前认证会话绑定。提交登录表单时，将识别结果填入 `captchaResponse`；校验不区分大小写。

### 3.5 提交登录

```http
POST /authserver/login?service=<URL 编码后的业务系统入口>
Content-Type: application/x-www-form-urlencoded
```

请求体：

| 字段 | 来源 |
| --- | --- |
| `username` | 学号或工号 |
| `password` | 使用当前盐值加密后的密文 |
| `lt`、`execution` | 登录页隐藏字段 |
| `_eventId` | 固定为 `submit` |
| `dllt` | 固定为 `userNamePasswordLogin` |
| `rmShown` | 固定为 `1` |
| `captchaResponse` | 验证码识别结果，仅在需要验证码时携带 |

响应分为以下几种情况：

| 响应 | 判断 | 处理 |
| --- | --- | --- |
| 302，`Location` 指向业务系统并带 `ticket=ST-...` | 认证成功 | 跟随跳转，进入业务系统 |
| 200 HTML，仍包含 `casLoginForm`，顶部 `#msg` 有提示 | 认证失败 | 读取 `#msg`；验证码错误时换图重试，账号密码错误时终止 |
| 200 HTML，出现「踢出会话」确认页 | 同账号已有会话 | 提交 `continue` 表单注销旧会话后继续 |
| 200 HTML，停留在 `improveUserInfo` 或 `modifyPassword` 页面 | 密码到期或需要完善资料 | 由调用方按业务规则续期或改密 |

常见提示文案：

- `无效的验证码`
- `您提供的用户名或者密码有误`

### 3.6 踢出旧会话

同账号已有会话时，登录响应会返回「踢出会话」确认页。页面包含：

```html
<form method="post" id="continue">
  <input type="hidden" name="execution" value="e1s2">
  <input type="hidden" name="_eventId" value="continue">
</form>
```

`execution` 的实际值以页面为准，上例仅为示意。向当前认证地址提交：

```http
POST <当前认证地址>
Content-Type: application/x-www-form-urlencoded

execution=e1s2&_eventId=continue
```

成功后会 302 回业务系统；若仍返回确认页，说明旧会话未注销成功。

### 3.7 回调业务系统

认证成功后，服务端会重定向到 `service` 指定的地址并附带 Ticket：

```text
<业务系统入口>?ticket=ST-...
```

客户端不需要解析 Ticket，只需复用同一个 Cookie 容器跟随跳转。Ticket 之后如何建立业务系统会话，由业务系统自行处理，不在本文范围。

## 4. 认证服务器 Cookie

认证服务器下发的 Cookie 中，与登录流程直接相关的有两项：

| Cookie 名 | 域 | 用途 |
| --- | --- | --- |
| `JSESSIONID` | `authserver.hebuee.edu.cn` | 认证服务器会话 |
| `CASTGC` | `authserver.hebuee.edu.cn` | CAS 单点登录票据，`Secure` |

认证服务器还可能下发其他内部 Cookie，按会话原样保存即可，不参与业务判断。

持有 `CASTGC` 时，访问其他接入统一认证的业务系统通常不需要重新输入密码。Cookie 名和域可能随平台升级调整，接入时以实际响应为准。Cookie 值属于敏感凭据，不应写入日志或文档。

## 5. 最小请求序列

```text
1. GET  业务系统入口
2. GET  /authserver/login?service=...
3. GET  /authserver/needCaptcha.html?username=...&pwdEncrypt2=pwdEncryptSalt
4. GET  /authserver/captcha.html?ts=...              # 仅 needCaptcha 为 true 时
5. POST /authserver/login?service=...               # 携带表单字段与 captchaResponse
6. POST <当前认证地址>                               # 仅出现踢出会话页时
7. GET  <service>?ticket=ST-...                     # 跟随 302
```

判断登录是否成功，以最终地址是否离开认证服务器、业务系统是否建立会话为准；不能只看登录请求的 HTTP 状态码。
